**网页看板数据机制**：定时任务每次跑完，会先把本次内容按固定结构写入 `../dashboard/data.js`（保留最近 7 天），网页打开时读取渲染。数据结构说明：

```
window.REPORTS = {
  "updatedAt": "更新时间",
  "reports": [
    {
      "date": "2026-08-31",            // 日期
      "morning": { ... },              // 早报（早报任务写入）
      "evening": { ... }               // 晚报（晚报任务写入）
    }
  ]
}
```

morning 结构：`title / source / sourceUrl / sections{要闻简讯[], 盘前人气股{}, 重点公告[], 今日新股}`
evening 结构：`sources[] / 博主观点[{author, view}] / 大盘概况{summary, metrics[]} / 连板梯队[] / watchlist[] / 短线逻辑[] / 板块热点[] / 市场情绪 / links{}`（**不含投资日历**，专版独立展示）

**博主观点**：晚报任务为每位博主（湖南人、行鱼复盘）提炼 150-300 字的**本人思路总结**（当日定性判断、主线逻辑、风险提示、次日展望），标注博主名称，渲染在看板晚报 Tab 顶部「🗣️ 博主观点」区块。这是用户最看重的部分——不是客观数据罗列，而是博主"怎么看、怎么做"。任务要求所有复盘图片必须逐张全部读取（可分多轮），不得因图片多而跳过。
calendar 结构（顶层，投资日历博主专版）：`[{ id, title, author, publishedAt, url, images["calendar/xxx.png"], events[{date, event}] }]`，保留最近 5 篇

**短线关注池（watchlist）**：晚报任务从当日连板梯队 + 板块热点自动提炼的 8-12 只短线强势股（最高标 → 次高板 → 板块龙头），每只包含 `name（股票名）/ role（板数·身份）/ sector（板块简称）/ note（一句话备注）`。看板第三个 Tab「📌 短线关注」展示；早报推送末尾附带前一日关注池（前 8 只）。

**短线逻辑（选股推导链）**：与 watchlist 配套，解决"名单有了但看不懂为什么选它"的问题。每个板块热点一条（4-6 条，按强度排序），字段为 `sector（板块名）/ stage（所处阶段：启动确认·主升加剧·情绪发酵·尾盘发力·轮动补涨·分歧退潮）/ why（板块为什么热：催化事件·政策·订单）/ chain（个股推导链 80-150 字）`。chain 写清楚板块内**谁是空间标杆（板数最高，常提示"位置高未入池/仅作情绪风向标"）→ 谁是趋势中军（订单或业绩实锤，入池）→ 谁是低位补涨（入池博卡位）→ 为什么不选其他（如"纯轮动脉冲未入池"）**，必须与 watchlist 实际入选情况一致。看板渲染在「📌 短线关注」Tab 个股列表**上方**的「选股思路：从板块到个股」区块（紫色卡片）。

**投资日历**（已从晚报正文移除，2026-08-31 起）：晚报 evening 不再包含投资日历摘要（与专版重复），抓取逻辑只服务于「📅 专版」——抓博主主页最新一篇 → 下载原图 → 提取完整事件 → 写入顶层 `calendar` 数组。**不设时效过滤**：博主最新一篇是什么就更新什么，完全跟随博主发帖节奏（原"超 5 天跳过"逻辑已删除）。

**投资日历专版版面（📅 Tab）**：看板第四个 Tab「📅 投资日历」独立展示「A股投资日历」博主的完整日历，**以原图展示为主**（博主文章内的日历表格大图直接复制到看板 `dashboard/calendar/` 目录，宽度 100% 全屏展示），下方配文字事件速览。数据结构为顶层 `calendar[]`（跨日期共享）：每篇含 `id / title / author / publishedAt / url / images[本地相对路径数组] / events[完整事件列表 15-25 条]`。晚报任务每次抓到博主新帖，会同时下载正文图片到 `dashboard/calendar/`（**命名统一为 `{id}_img{n}.{ext}`**，与现有 `20a9hu1mmef_img1.png` 一致）、提取完整文字事件，然后插入 `calendar` 最前（按 id 去重），保留最近 5 篇；看板内可点击历史文章切换查看。目前已有 2 篇：9 月日历（8/30，含原图）、8/22 下周要变天。更新不限时效，完全跟随博主发帖节奏；博主不更新则专版保持最近一篇。

**运行日志**：每次任务运行完，会把数据源抓取状态 / 看板写入 / git 提交 / 部署 / 微信通知结果追加到 `logs/{日期}.md`，可随时查看「今天推了什么、有没有报错」。

**git 版本管理**：`A股推送系统` 目录已初始化 git 仓库，早晚报任务写入数据后各自动提交一次（`看板数据 {日期} 早报/晚报`），data.js 被写坏时可随时回滚。

**前端版本号自动化**：`tools/bump_version.sh` 在每次部署前自动把 index.html 中资源引用的 `?v=` 刷新为当前时间戳，浏览器不再缓存旧文件（曾踩过"网页里没有"的缓存坑，现由脚本自动处理，无需再手改版本号）。

> 注意：早晚两个任务各自只写自己的字段（morning/evening），基于读取现有文件合并，不会互相覆盖。改动看板结构时两个任务的 prompt 都要同步。
