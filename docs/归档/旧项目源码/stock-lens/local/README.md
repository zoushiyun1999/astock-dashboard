# stock-lens 本地版（无后台）

**没有服务器、没有常驻进程、没有端口占用、没有数据库服务。**

取数在本机跑（跑完即退），展示是纯静态文件。同一个站既能双击 `web/index.html`
离线看，也能一键发布到边缘网络，在外地用手机看。

## 目录

```
local/
├── config.json            配置：选股预设 / 板块 / 自选股 / 博主源清单
├── update.py              数据更新脚本（跑一次就退出；RUN_HOURS 定义每日轮次）
├── update.bat             Windows 一键运行
├── mkschedule.py          生成计划任务定义（XML，4 轮触发）
├── install_schedule.bat   注册每日定时任务（含"错过则开机补跑"）
├── publish.bat            取数 + 发布到 EdgeOne Makers（在外访问用）
├── verify.js              冒烟测试：验证渲染逻辑不报错（28 项断言）
├── schedule/              ← 自动生成，计划任务定义
├── logs/                  ← 自动生成，分槽日志 slot0..slot3.log
├── web/
│   ├── index.html         前端（纯静态，全离线，不引任何 CDN）
│   └── data.js            ← 自动生成，勿手改
├── data.snapshot.json     ← 自动生成，留档（降级时读它）
└── update.log             ← 自动生成，运行日志（全轮次汇总）
```

## 用法

**日常（本机看）**：双击 `update.bat` → 十秒内 → 打开 `web/index.html`。

**自动（本机看）**：双击 `install_schedule.bat`，注册每天 **4 轮**更新：
`07:00 / 12:00 / 16:00 / 22:00`（分别服务早报、盘中、收盘、晚报）。
细节见下方「计划任务为什么要做成 XML」。

**外出看（手机）**：双击 `publish.bat` → 取数并发布到 EdgeOne Makers。
首次需先登录一次：`npx edgeone login --site china`（会弹浏览器授权）。

**改动**：编辑 `config.json`，改完再跑一次 `update.bat`。

## 为什么不需要后台

后台服务存在的理由是「随时响应请求」。这个场景的数据一天只更新一次，
用不上这个能力。所以把「在线服务」换成「离线批处理 + 静态文件」：

```
定时任务 / 双击 bat
      ↓
update.py  调 CLI 取数 → 写 web/data.js → 退出
      ↓
web/index.html  用 <script src="data.js"> 读数据，浏览器直接渲染
```

`update.py` 只在运行的十几秒内存在，与"后台"无关。

### 关键技术点

**数据为什么写成 `data.js` 而不是 `data.json`？**

浏览器在 `file://` 协议下用 `fetch('data.json')` 会被同源策略拦截
（本地文件被视为 opaque origin，读不到）。而 `<script src="data.js">`
是经典脚本加载，不受同源限制。所以数据以 `window.DATA = {...}` 的形式写出。

这是"双击 HTML 就能看"能成立的前提，也是这个站能直接丢到任何静态托管的原因
——它本来就只有一个 HTML 加一个 JS，全部相对路径引用。

## 计划任务为什么要做成 XML

本机不可能 7×24 开机。若任务固定在某个时刻触发，那个时刻碰巧关机就整天不跑。

Windows 有对应的设置项 —— **"错过计划时间后尽快启动"** —— 但它**只存在于
XML 定义和 PowerShell 两种途径里，`schtasks /Create` 的命令行参数没有这个开关**。
本机不能假定 PowerShell 执行策略开放，所以走 XML（`mkschedule.py` 生成）。

配套的幂等检查在 `update.py` 里，判据是**按轮次的**（不是按天）：
先看当前这一轮是否已经成功取过数，是则直接退出，不重复打第三方接口。

轮次表定义在 `update.py` 的 `RUN_HOURS`，**必须与 `mkschedule.py` 的 `RUN_HOURS` 保持一致**
—— 少一个触发点，某一轮就永远不会跑。

两个机制合起来的效果：

| 情况 | 结果 |
| --- | --- |
| 该轮时间点电脑开着 | 正常更新 |
| 该轮时间点电脑关着 | 下次开机后自动补跑 |
| **同一轮**已更新过又触发 | 立即退出，不重复取数 |
| 早报轮跑过，中午轮触发 | **正常跑**（不同轮次互不影响） |
| 凌晨 2–7 点开机 | 昨日任一轮成功即视为收工，不逐轮补跑 |
| 当天全部取数失败 | 不锁死，允许后续重试 |

手动强制重跑：`python update.py --force`

## 博主内容怎么采的

只用 Python 标准库（`urllib`），**不抓详情页、不下载图片、不落数据库**。
读的是列表接口自带的标题 + 正文摘要 + 股票标签，图片留在原站，点击卡片跳原文。

这是速度的关键：同需求的第一版实现（抓详情页 + 下载图片 + SQLite 落库）
单次要 **20 分钟**，现在 **0.9 秒**。

两个站各有解析难点（已在 `src/collectors/blogs.py` 注释里记录，避免重复踩）：

- **韭研公社**用 Nuxt SSR，数据内联在 `window.__NUXT__`，且是压缩后的 IIFE
  —— 字段名会被替换成变量。解法是按 `title:"..."` 锚点切区块，块内独立取字段。
- **淘股吧**列表按时间**正序**排列（抓到的是旧文），且翻页接口需登录。
  解法是单页全抓，从标题解析日期后倒序取最新。

## 发布到 EdgeOne（外出访问）

`publish.bat` 做两件事：跑 `update.py`，然后把 `web/` 上传到 EdgeOne Makers。

几个实测确认过的点：

- **不需要买服务器**，用的是边缘网络的静态托管
- **未备案也能用** —— 平台会分配一个子域名（形如 `xxx.edgeone.cool`），
  实测国内访问首字节约 0.3–0.5 秒
- 自己的域名需要在 EdgeOne 控制台绑定；未备案的域名只能走境外节点

## 数据取不到时怎么办

数据源由第三方维护，会抖（本项目实测到过 `service error`）。
脚本的应对是**单项失败不影响整体，失败项自动回落上一次留档**，
前端会在顶部横幅明确标注哪些项是旧数据、旧到哪一天。

不假设"失败后重跑就能恢复"——实测过同一时刻有的接口正常、有的报错。

## 已知边界（"无后台"的代价）

**不能实时查任意股票。** 页面展示的是 `config.json` 里预置的内容。
想看配置之外的东西：

1. 加进 `config.json` 的 `watchlist`，重跑一次
2. 或者在 WorkBuddy 对话里直接问（本机已连行情 CLI，无需开网页）

**博主摘要是"目录之后的正文开头"，不是全文摘要。** 部分博主的帖子开头是固定目录
（"1、要闻简讯 2、三大报要点…"），脚本会把这段目录剥掉，但摘要整体仍是原文截断，
不是 LLM 生成的归纳。想读全文请点卡片进原文。

**页面数据的新鲜度取决于本机最近一次成功运行。** 如果用发布方式在外访问，
电脑长期关机期间看到的是出发那天的数据 —— 页面顶部会显示实际数据时间。

## 依赖

- Node ≥ 18（本机已装）
- Python ≥ 3.9（仅用标准库）
- `westock` CLI + westock-tool（本机已装）
- 发布功能额外需要 `edgeone` CLI（`npx` 会自动拉取，无需预装）

`config.json` 的 `paths` 字段留空即自动探测；探测不到时填绝对路径。

## 自检

```bash
node verify.js
```

用最小 DOM 桩真跑一遍前端渲染逻辑，断言数据确实被渲染成了表格与卡片
（含"博主观点"面板的 4 组 / 24 条目 / 外链 / 股票 chips）。
