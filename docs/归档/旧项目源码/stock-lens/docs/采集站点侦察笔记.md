## 二、robots.txt 原文要点

### 淘股吧

```
User-agent: *

Disallow: /view?topicID=*
Disallow: /Reply/*
Disallow: /new/ngb/*
Disallow: /new/dav/*
```

- 禁止范围很窄。**注意 `/view?topicID=*` 是帖子正文页，禁止访问。**
- 实际可用的正文路径是 `/a/{短码}`（见下文），**未被禁止**。
- 接入时务必遵守：不要走 `/view?topicID=`。

### 韭研公社

```
User-agent: *
Disallow: 
Sitemap: https://www.jiuyangongshe.com/sitemap.xml
```

- `Disallow:` 值为空 → 实质全站允许。
- 有 sitemap，可作列表发现入口。
- 域名提示：`jiuyangongshe.com` 与 `jiucaigongshe.com` 为同一站点（站名"韭研公社"，原"韭菜公社"），sitemap 内链接用的是后者的域名。

### 雪球

```
# Use of Xueqiu Content: Without our express permission, you are prohibited from using
# any content from Xueqiu for the development, operation, or maintenance of any
# Artificial Intelligence (AI) system. This includes, but is not limited to, using our

# Creation of Datasets: Without our express permission, you are prohibited from creating

```

```
User-agent: ChatGPT-User / GPTBot / ClaudeBot / Claude-Web / CCBot / PerplexityBot /
            Amazonbot / Applebot / Applebot-Extended / Meta-ExternalAgent / Diffbot /
            FacebookBot / Google-Extended / Timpibot / YouBot / omgili / Yisouspider
```

**结论：雪球的服务条款明文禁止把其内容用于 AI 系统（含 RAG）、禁止创建含其内容的归档/缓存数据集。** 用户方案（抓取 → LLM 摘要 → 存本地库）三项全部命中。且 `Disallow: /*.json` 封禁了所有 JSON 接口。**技术侦察到此为止，不再深入绕过网关的方案。**

## 四、韭研公社内部 API（已定位，未突破鉴权）

**基址**：`https://web-api.jiuyangongshe.com`
**来源**：前端 bundle `https://www.jiuyangongshe.com/_nuxt/*.js` 静态分析得出
**规模**：共 130 个 `/api/vN/` 端点

### 与需求直接相关的端点

| 端点 | 用途推断 |
| --- | --- |
| `/api/v1/user/newest-article-tool` | **指定博主最新文章** ← 核心需求 |
| `/api/v1/user/homepage` | 用户主页 |
| `/api/v1/user/info` | 用户信息 |
| `/api/v1/user/fans/follow-list` | 关注列表 |
| `/api/v1/article/hot` | 热门文章 |
| `/api/v1/article/step` | 文章内容（分段） |
| `/api/v1/product/article/detail` | 文章详情 |
| `/api/v1/product/article/list` | 文章列表 |
| `/api/v1/article/comment/list-pc` | 评论列表 |
| `/api/v1/article/rank-board` | 排行 |
| `/api/v1/industry/detail` | 行业 |

### 鉴权与付费信号

- 存在 `/api/v1/user/login`、`/api/v1/user/login/sms`、`/api/v1/user/login/wx-pc` → 有登录体系。
- 存在 `/api/v1/article/read/pay`、`/api/v1/product/investment/*`、`/api/v1/pay-order/*` → **存在付费内容与付费专栏体系**。

### 实测结果

直接 GET `https://web-api.jiuyangongshe.com/api/v1/article/hot`（带浏览器 UA + Referer）返回：

```
502 Bad Gateway (nginx)
```

`/api/v1/user/homepage`、`/api/v1/user/newest-article-tool` 同为 502。

**解读**：502 而非 401/403，说明 nginx 网关在路由前就拒绝了请求 —— 大概率校验了 App 侧特有的请求头、签名或参数。**未继续尝试绕过。**

> **后续接入建议**：优先用浏览器（Playwright）加载页面并拦截 XHR，从真实请求中观察所需头部，而不是逆向推测。若页面加载后正文正常出现，说明只需浏览器上下文，不需要伪造签名。
> **付费内容边界**：即便技术上可达，也只采集公开可见部分，不绕过付费墙。

## 五、采集实现建议

### 淘股吧（一层，全自动）

- 工具：`httpx` + 简单 HTML 解析（文章标题多在内链文本中，正文需单独取 `/a/{code}` 页）
- 发现机制：定时拉 `/blog/{用户ID}` 取最新 `/a/{code}` 列表，与本地库比对去重
- 频率：≥ 60 分钟一次
- 预估：3–4h

### 韭研公社（二层，半自动）

- 列表层：`/square`、`/study_hot` 等栏目页可直接 httpx 解析（首页实测含 7,513 个中文字符，内容在 HTML 中）
- 详情层：HTML 中不含正文（实测仅 481 个中文字符，只有标题与免责声明），需 Playwright 渲染，或按上文用浏览器拦截 XHR 找出可复用的请求
- **内存约束**：Playwright 必须串行，峰值 300–500MB
- 预估：5–7h

### 雪球（三层，手动）

- 方案：浏览器书签一键投喂（选中正文 → 提交到本地接口）
- **不做自动抓取**，理由见第二节
- 预估：2–3h

## 六、可插入的适配器抽象

三个站点横跨三种完全不同的技术形态，说明适配器必须配置驱动。建议抽象成两个钩子：

```
adapter:
  name: tgb
  enabled: true
  discover:            # 如何发现"有哪些新内容"
    type: html_list    # 或 json_api / sitemap / manual
    url: "https://www.tgb.cn/blog/{user_id}"
    item_selector: "a[href^='/a/']"
  fetch:               # 如何取正文
    type: html_page
    url: "https://www.tgb.cn{path}"
    content_selector: "article"
  rate_limit: "60m"
  respect_robots: true
```

新站点接入目标成本：**1–3h**。每季度预留一次适配器巡检。
