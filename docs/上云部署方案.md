# 上云部署方案（把定时任务从本机搬到服务器）

> 2026-09-21 制定。目标：**摆脱「电脑必须一直开着」**，让早报/晚报/选股/验证在服务器上自动跑。
>
> 状态：**代码已就绪，尚未在服务器上实测**（缺 LLM API key 与 ECS 实例）。

## 1. 为什么能搬 —— 三层架构里只有一层要改

原模式的瓶颈不在「脚本」，而在**中间的分析层**由桌面端 Agent 完成（读图、提炼、定性）。

| 层 | 组件 | 上云处置 |
|---|---|---|
| 抓取层 | `fetch_jy_article.js`（韭研）、`fetch_tgb.js`（淘股吧）、东财/新浪接口 | **原样可用** |
| 分析层 | 原为 WorkBuddy Agent | **已替换**为 `lib/llm.js` + `lib/prompts.js` |
| 写入与发布层 | `merge_report.js`、`check_codes.js`、`publish.sh`、`verify.js`、`screener.js`、`health_check.js` | **原样可用** |

## 2. 新增文件

| 文件 | 作用 |
|---|---|
| `tools/lib/llm.js` | LLM 调用层（OpenAI 兼容协议，零依赖）。支持文本与视觉、超时重试、JSON 解析容错、**按魔数判断图片类型** |
| `tools/lib/prompts.js` | 所有 prompt 集中定义（早报提炼 / 晚报结构化 / 读图转录） |
| `tools/job_morning.js` | 早报：取数 → LLM 提炼 → `merge_report` → `check_codes` → `publish` |
| `tools/job_evening.js` | 晚报：抓两个博主 → 切片 → 视觉模型转录 → LLM 结构化 → 写入 → 发布 |
| `tools/fetch_tgb.js` | 淘股吧取数器（列表 / 文章 / 正文图下载，含 `_max` 404 自动回退） |
| `tools/slice_image.py` | 长图切片（Pillow）。**必需** —— 实测有 530×6157 的超长表格图 |
| `tools/cron.sh` | cron 统一入口（时区断言 + flock 并发互斥 + 环境变量加载） |
| `tools/deploy_ecs.sh` | ECS 环境初始化（幂等） |

## 3. 环境变量（写在 `~/.astock.env`，**不入库**）

```bash
umask 077
cat > ~/.astock.env <<'ENV'
# 智谱 BigModel —— 文本与视觉各有一个永久免费模型，零成本起步
LLM_API_KEY=<你的 API Key，形如 id.secret>
LLM_BASE_URL=https://open.bigmodel.cn/api/paas/v4
LLM_TEXT_MODEL=glm-4.7-flash
LLM_VISION_MODEL=glm-4.6v-flash
# 可选
LLM_TIMEOUT_MS=180000
LLM_MAX_RETRY=3
LLM_VERBOSE=1
PYTHON_BIN=python3
ENV
```

- **必须用支持视觉的模型**（`LLM_VISION_MODEL`）：湖南人与行鱼的正文**全是图片**，没有文字捷径。
  仅凭这一条就排除了 DeepSeek（它没有开放的视觉 API）。
- **鉴权已自动适配两种格式**：智谱的 `<id>.<secret>` 会按 HS256 签 JWT，百炼 / DeepSeek 的
  `sk-xxx` 直接作 Bearer。换平台只改 `LLM_BASE_URL` 与模型名，**不用改代码**。
- 仓库根的 `.gh-token` 单独配置（需 `Contents: RW` + `Workflows: RW`）。

### 3.1 成本对比（按本项目的实际用量估算）

日报送模型的量级：早报约 12K 输入 token；晚报约 50 张切片（湖南人 5 图 + 行鱼可达 46 图，
切片后约 50~60 张）× 约 1.5K token ≈ 80K 输入 token。

| 方案 | 文本模型 | 视觉模型 | 约合每天 | 说明 |
|---|---|---|---|---|
| **智谱免费档（默认）** | glm-4.7-flash | glm-4.6v-flash | **¥0** | 免费但有速率限制；质量若不达标再升级 |
| 智谱付费档 | glm-4.7-flash | glm-4.6v-flashx（0.15/1.5 元/百万） | 约 ¥0.05 | 升级只需改 `LLM_VISION_MODEL` |
| 阿里云百炼 | qwen-flash（0.8/2） | qwen3-vl-flash（0.18/1.8） | 约 ¥0.1 | 与 ECS 同厂；新用户有 100 万 token / 90 天额度 |
| DeepSeek | deepseek 系列很便宜 | **无视觉模型** | — | **不可用**：晚报读图做不了 |

结论：**先用智谱免费档**。它是唯一能覆盖「文本 + 视觉」且成本为零的组合；
真跑起来质量不够时，改一行环境变量升级到 `glm-4.6v-flashx` 即可，成本仍不到每天一毛钱。

## 4. 部署步骤

1. **领机器**：阿里云 ECS 免费试用个人版 → `2核2G 经济型e`、`Alibaba Cloud Linux 3`、地域选**内地**（杭州/北京/广州/成都），预装应用一个都不勾。
2. **传代码**：服务器上 `git clone`，或本机打包上传后解压。
3. **初始化**：`cd <repo> && sudo bash tools/deploy_ecs.sh`（幂等，可重复跑）。
4. **配凭据**：按第 3 节写 `~/.astock.env` 与 `.gh-token`。
5. **装 crontab**（`crontab -e`）：
   ```
   0  7  * * *    cd REPO && bash tools/cron.sh health    >> logs/cron.log 2>&1
   30 8  * * *    cd REPO && bash tools/cron.sh morning   >> logs/cron.log 2>&1
   10 15 * * 1-5  cd REPO && bash tools/cron.sh screener  >> logs/cron.log 2>&1
   0  21 * * *    cd REPO && bash tools/cron.sh evening   >> logs/cron.log 2>&1
   30 21 * * 1-5  cd REPO && bash tools/cron.sh verify    >> logs/cron.log 2>&1
   ```
6. **停掉本机的 7 个 automation**（否则两边同时写 data.js，会互相覆盖）。

## 5. 验收清单（按顺序，每步都要过）

```bash
node tools/lib/llm.js --check      # 配置自检；缺 key 退 1
node tools/lib/llm.js --ping       # 真实调用一次，验证鉴权与出网
node tools/fetch_tgb.js --blog 444409 --list --n 5    # 淘股吧可达性
node tools/job_morning.js --dry    # 早报：只抓取+提炼，不写盘
node tools/job_evening.js --dry    # 晚报：会真的下载图片并调用视觉模型
node tools/health_check.js         # 数据体检（有 WARN 退 1）
```

`--dry` 的输出要**人工比对**当天线上看板的内容，确认不是「格式对但内容空」。

## 6. 已知风险（未验证项）

| 风险 | 说明 | 应对 |
|---|---|---|
| **机房 IP 的风控差异** | 抓取源从家用宽带 IP 换成机房 IP，反爬策略可能不同 | 第 5 节的 `fetch_tgb.js --list` 就是探针；失真明显则改用家用常开设备方案 |
| **视觉模型读图质量** | 旧模式由 Agent 逐张读图；换成 API 后表格转录准确度**未实测** | 用 `--dry` 跑几天，对比人工核对 |
| **成本** | 晚报每天约 50~60 张切片送模型（湖南人 6 图、行鱼可达 49 图） | 随时可用 `--max-slices N` 封顶；观察一周后再定 |
| **ECS 试用到期** | 额度耗尽或满 3 个月 → **实例自动释放，数据只保留 72 小时** | 见第 7 节 |
| 投资日历未接入 | 原晚报含「投资日历专版」（韭研公社不定期发布） | **尚未实现**，见第 8 节 |

## 7. 试用期到期前必须做的事

`publish.sh` 已经把数据同步到 GitHub，所以**数据本身不怕丢**。但要无缝切换：

1. 在**释放前**购买正式实例（轻量应用服务器量级即可，脚本全部零依赖）。
2. 新机器上重跑 `deploy_ecs.sh` + 恢复 `~/.astock.env` 与 `.gh-token`。
3. 老实例释放前确认 `node tools/health_check.js` 与线上页面正常。

## 8. 尚未实现 / 后续

- **投资日历专版**：`job_evening.js` 目前不产出 `calendar` 字段（该字段可省略，`merge_report` 允许）。
  补齐需要：抓韭研公社日历博主页 → 下载原图 → 用视觉模型判断「是否真含日历内容」
  （历史坑：抓到过一张 2.2MB 的牡丹花装饰图，必须校验）→ 写入顶层 `calendar`。
- **两个看门狗 automation**（早报补跑 10:00 / 晚报补跑 22:30）：上云后**冗余，可直接停用** ——
  它们的存在意义就是「本机可能没开机」。服务器常驻后，失败会由 `logs/ALERT.md` 与
  `health_check.js` 兜住。

## 9. 回滚

本方案**不改动**任何现有脚本的行为，只新增文件。回滚 = 停掉服务器 crontab + 重新启用本机
7 个 automation。旧路径（Agent 驱动）完全保留可用。

## 10. 实测记录（2026-09-21，本机验证部分）

- 淘股吧 `m.tgb.cn` 从本机可达；**不带尾部斜杠**才是 200（`/blog/444409/` 会 404）。
- 博客列表日期是完整格式 `2026-09-21 17:04`；列表实测**降序**（与旧文档「正序」说法相反）→
  代码里按时间自行排序，不依赖页面顺序。
- 正文图：`loadImg(this,"…_max.png")` + `data-original="…_760w.png"`；`src` 恒为占位符。
  **`_max` 可能 404（CDN NoSuchKey）** → 必须回退 `_760w`。
- **URL 后缀 `.png` 但实际内容是 JPEG**（魔数 `ff d8 ff e0`）→ 一律按魔数判断。
- 两个博主的正文**都是图片，页面无正文文字**。旧 prompt 称「正文文字在 `gtgioMsg` 的
  subject 属性里」是**错的** —— `gtgioMsg*` 是评论区。
- 长图必须切片：530×6157 整张交给模型完全无法阅读；按 1200px/段 + 80px 重叠 + 1.5x 放大
  切成 6 段后可清晰读出「市场连板股」表格（代码/名称/末次时间/连板数/原因）。
