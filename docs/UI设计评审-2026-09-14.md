# A股速览 · 看板 UI 设计评审

> 评审日期：2026-09-14
> 评审对象：`dashboard/`（index.html 121 行 / style.css 396 行 / app.js 693 行）
> 方法：Edge headless + CDP 实测（390px 手机宽 / 1280px 桌面宽），5 个 Tab 全部渲染后取
> `getBoundingClientRect()` 与 `getComputedStyle()` 真实值，对比度按 WCAG 2.1 公式计算。
>
> **结论：结构（信息架构、Tab 划分、数据组织）是好的，问题集中在「视觉系统层」——
> 配色没有语义、字阶没有收敛、可读性与触控尺寸有硬伤。这三类都是 CSS 层可改的，
> 不需要动数据结构。**

---

## 一、P0 · 会直接造成误读的问题

### 1. 颜色没有语义系统：红绿同时承担「价格」和「非价格」含义

实测统计：页面共出现 **13 种文字色**（不含白色），而红/绿两个最敏感的颜色被复用到了语义相反的场合。

| 颜色 | 值 | 当前被用在 | 问题 |
|---|---|---|---|
| 红 `--up` | `#e03131` | 涨幅数字、4连板标签、板块排名第1、个股「角色」标签、晚报未读红点、风险公告圆点、高位风险徽章、大盘概况标题点 | 「涨」和「风险」共用一色 |
| 绿 `--down` | `#0ca678` | 跌幅数字、**今日新股**卡片圆点、**近期重复推荐**的次数胶囊（连排 10 个）、板块排名第4、低位/安全徽章 | 「跌」和「正面强调」共用一色 |

最扎眼的一处：**短线 Tab 的「近期重复推荐」列表**里，10 行「5次 / 4次 / 3次」全部是绿色胶囊。
按 A 股习惯读，用户第一反应是"这些股票在跌"，而实际含义是"被推荐过 5 次"。

第二处：**板块热点的序号是 6 色彩虹**（红 → 橙 → 橙黄 → 绿 → 蓝 → 紫）。
第 4 名是绿色，与"跌"同色，而第 1 名是红色，与"涨"同色——排名色被误读成涨跌色。

第三处：这些颜色还是**按 `nth-child` 位置硬编码**的（`.ladder li:nth-child(2)`、`.sector:nth-child(4)`、
`.watch li:nth-child(3)`）。哪天板块从 6 个变成 5 个，颜色就整体错位，且没有任何报错。

**建议：三层语义，互不越界。**

| 层 | 允许用色 | 只用于 |
|---|---|---|
| 价格层 | 红 `#e03131` / 绿 `#0ca678` | 涨幅、跌幅、指数点位——**仅数字** |
| 风险层 | 红 / 橙 / 蓝 三档 | 状态徽章（高位风险 / 中性待确认 / 低位安全） |
| 结构层 | 藏青单色阶（`#0F172A` → `#eef0f4`） | 标题、序号、排名、板块名、标签、导航 |

关键改动：**「低位 / 未启动 / 安全」这类正面状态不要用绿色**，改用蓝色（`#185fa5` on `#e3f0fb`），
把绿色完整地留给"跌"。排名序号不再用色相区分，改为藏青单色阶的深浅或纯数字。

### 2. 量价表 9 列，55% 的内容在屏幕外，且没有任何滚动提示

实测（390px 手机）：`.sc-wrap` 可视宽 **330px**，内容宽 **514px**，横向溢出 **184px**。

用户在手机上只能看到 `# / 名称 / 板块 / 涨幅 / 换手` 五列，而**恰好被挡住的
`市值 / 量比 / 连阳 / 均线上` 四列，正是这份表的筛选依据**。更要命的是没有任何视觉提示
（无渐隐遮罩、无"← 滑动查看 →"、无滚动条），用户根本不知道右边还有内容。

**建议（三选一，推荐 B）**
- **A. 精简列**：把「市值/量比/连阳/均线上」折成名称下方的副行小标签（两行内），9 列压到 5 列，彻底不滚。
- **B. 保留表格 + 加滚动引导**：右侧加 24px 白色→透明渐隐遮罩；表头右端加「滑动查看 →」；
  首屏自动 `scrollLeft` 轻微位移一次做视觉暗示。
- **C. 改卡片列表**：每只股票一张小卡，字段竖排。信息最完整但页面会变很长。

### 3. 投资日历原图：2008×17040 塞进 330px 宽，实际不可读

实测：日历原图 `naturalSize` = **2008 × 17040**，渲染尺寸 **330 × 2800**。
换算下来原图被压缩到 **1/6.1**，原图里的表格文字到手机上只有约 2px 高——**完全无法阅读**。

代价：「日历原图」卡片高 **3247px**，「事件日历」卡片高 **2086px**，整个日历 Tab 高 **5906px ≈ 7.5 屏**。
而页面下方本来就已经有一份结构化的「事件日历」列表，两者内容高度重复。

**建议**
- **A（推荐）**：「日历原图」默认折叠成一个入口按钮（"查看原图（长图）"），点击后全屏打开，
  支持双指缩放。首屏只留结构化的「事件日历」。
- **B**：原图按宽高比切成 N 段（每段约 1 屏），逐段展示，滑动即换段。
- **C**：去掉原图，只保留「事件日历」。省最多的体积，但丢失博主原图的排版信息。

## 二、P1 · 一致性与可用性

### 4. 字号失控：15 种字号，其中 5 种挤在 2px 区间内

实测 `font-size` 分布：

| 字号 | 出现次数 | 字号 | 出现次数 |
|---|---|---|---|
| 10px | 41 | 13px | 14 |
| 10.5px | 8 | 13.5px | 87 |
| 11px | 48 | 14px | 41 |
| 11.5px | 35 | 14.5px | 8 |
| 12px | 52 | 15px | 69 |
| 12.5px | 238 | 17 / 18 / 20 / 40px | 5 |

- **`12px / 12.5px / 13px / 13.5px / 14px` 五个字号挤在 2px 区间**，人眼完全无法分辨，
  纯粹是"顺手写了个数字"的结果。仅 `12.5px` 一个值就用了 238 次。
- **小于 12px 的共 132 处**（10 + 10.5 + 11 + 11.5），手机上 10px 中文基本读不清。

**建议：收敛到 6 级字阶**

| 用途 | 现在 | 建议 |
|---|---|---|
| 微标签（徽章 / 条件胶囊） | 10 / 10.5 / 11 | **11px** |
| 辅助说明（时间、计数、脚注） | 11.5 / 12 | **12px** |
| 次要正文 | 12.5 / 13 | **13px** |
| 正文基准 | 13.5 / 14 / 14.5 / 15 | **14px** |
| 小节标题 / 股名 | 17 / 18 | **17px** |
| 页面主数字（指数点位） | 20 / 40 | **22px** |

### 5. 对比度不达标：6 处低于 WCAG AA 的 4.5:1

按 WCAG 2.1 公式实测（文字色 on 背景色）：

| 位置 | 颜色组合 | 实测对比度 | 判定 |
|---|---|---|---|
| `--ink-3`（次要文字，**用了 60 处**） | `#9aa1af` on `#ffffff` | **2.60:1** | 不达标 |
| 状态徽章 · 待确认 | `#868e96` on `#e9ecef` | **2.80:1** | 不达标 |
| 健康条 · 警示 | `#e67700` on `#fff9db` | **2.83:1** | 不达标 |
| 状态徽章 · 中性 | `#e8590c` on `#ffe8cc` | **3.01:1** | 不达标 |
| 状态徽章 · 低位 | `#2b8a3e` on `#d3f9d8` | **3.81:1** | 不达标 |
| 筛选条件胶囊 | `#1971c2` on `#e7f2fb` | **4.42:1** | 勉强不达标 |
| `--ink-2`（次级文字） | `#5b6270` on `#ffffff` | 6.13:1 | 达标 |

`--ink-3` 是重灾区：`11px` 的 `.sc-table th`、`11.5px` 的 `.wl-desc` / `.cal-meta` / `footer`、
`12px` 的 `.date-nav .lbl` 全部用它。**这些恰好是需要看清的说明文字。**

**建议**：`--ink-3` 从 `#9aa1af` 提到 **`#6b7280`**（≈4.8:1）；徽章前景整体加深一档，
并把徽章字号统一到 11px 以上。改一个变量就能一次修掉 60 处。

### 6. 触控目标小于 44px

| 元素 | 实测尺寸 | 判定 |
|---|---|---|
| `.tab`（Tab 按钮） | 72 × **44px** | 达标 |
| `.date-nav button`（前一天 / 后一天） | 63 × **27px** | **过小** |
| `.cal-m`（期数 / 月份切换胶囊） | 57 × **27px** | **过小** |

`27px` 的高度在手指上很容易点偏，且在日历 Tab 里 `.cal-m` 是**唯一的期数切换入口**。

**建议**：两者 `padding` 提到 `10px 14px` + `min-height: 44px`。

### 7. 没有粘性导航，切 Tab 要滑回顶部

`.tabs` 是 `position: relative`，`header` 也不是 sticky。而页面高度实测：

| Tab | 页面总高 | 折合屏数 |
|---|---|---|
| 日历 | 5906px | 7.5 屏 |
| 早报 | 3324px | 4.4 屏 |
| 短线 | 2421px | 3.2 屏 |
| 量价 | 2130px | 2.8 屏 |

在日历 Tab 里看完要换 Tab，必须一路滑回顶部——这是**手机上最高频的操作**。

**建议**：`header` 在滚动后收起为 44px 的窄条，`.tabs` 固定在顶部（`position: sticky; top: 0`），
滚动时只保留 Tab 栏，`z-index` 高于卡片。

### 8. 「大盘概况」指标卡的颜色规则不一致

同一行三张卡，同为下跌，呈现却是三种：

- 上证指数 `3934.00` → **绿色**（有 `up:false`）
- 深证成指 `-1.08%` → **灰色**（数据里没有 `up` 字段）
- 创业板指 `-0.49%` → **灰色**（同上）

前端逻辑是 `x.up === true ? ' up' : (x.up === false ? ' down' : '')`，字段缺失就静默不上色。
用户无法解读"为什么一个绿两个灰"。

另外**网格是 `repeat(3, 1fr)`，但当前有 7 个指标**，末行只剩「封板率」一张卡孤零零挂在左边，
右侧留两个空位，视觉重心失衡。

**建议**
- 上色改为按**数值符号**判断（`parseFloat(v) < 0` 即绿），字段缺失也能兜底；
- 网格改 `repeat(auto-fit, minmax(96px, 1fr))`，或让最后一张卡跨列补满。

## 三、P2 · 阅读体验与工程一致性

### 9. 三处「文字墙」

| 位置 | 现状 |
|---|---|
| 博主观点 | 单段 1000+ 字，13.5px / line-height 1.75，占 1.5 屏 |
| 市场情绪 | 单段 200+ 字，无分段 |
| 短线个股 reason | 每只 4–6 行连续文本，「催化：」「风险：」没有视觉强调 |

而且**「博主观点」排在「大盘概况」之前**——用户打开晚报，第一眼是一大段转述文字，
而不是最重要的指数数字，**信息优先级是倒的**。

**建议**：把「大盘概况」提到最前；长文本按 `催化 / 风险 / 处置` 拆成带小标签的行；
关键数字（点位、涨跌幅、亿元）加粗或换色。

### 10. Header 与 Footer 信息完全重复

4 个数据源（早报 / 晚报 / 量价 / 投资日历）的状态，在 **header 右上角**出现一次，
在 **footer** 又原样出现一次，两处都是 11px。header 右上角那四行还要挤在深色渐变上。

**建议**：header 只保留最简的一行汇总（如「🟢 全部正常」或异常时才展开详情），
明细统一收到 footer；或者反过来。**不要两处都放。**

### 11. 桌面端 Header 全宽、内容列窄——视线跨度 1100px

实测 1280px 视口：`header` 宽 **1265px**（全宽），而 `.wrap` 内容列宽 **528px**、起点 `x=369`。
于是品牌 logo 在 `x≈18`、数据源状态在 `x≈1100`，而正文卡片在中间 `369–897`。
用户的视线要在两端来回跳 1100px。

**建议**：给 `header` 内层加一个 `max-width: 560px; margin: 0 auto` 的容器，
让 header 内容与正文列对齐；或整体放宽到 720px 并做成双栏（左侧导航 + 右侧内容）。

### 12. 链接不可识别

`.link-row a { color: var(--brand) }`，而 `--brand` 是 `#0F172A`——**接近黑色**，
且没有下划线（只有 hover 才有）。「🔗 原文：9月14日开盘必读资讯」看起来就是一行普通文字。

**建议**：链接用可识别的蓝（`#1971c2`），或加 1px 下划线；至少加一个 `↗` 后缀。

### 13. 「卡中卡」层次过多且对比度为零

`body > .wrap > .card(白底) > .sector(#fafbfd + border)` —— `#fafbfd` 与 `#ffffff`
的明度差几乎为 0，嵌套层级看得见边框却看不出层次。

同时**排名视觉有三套**：`.ladder .board`（红色胶囊）、`.sector .rank`（彩色方块）、
`.watch .rank`（圆角方块 + 数字）。同一站内三种排名样式。

**建议**：统一为一套排名组件（藏青单色阶 + 数字），嵌套色块改用左侧 3px 色条而非整体底色。

### 14. 「近期重复推荐」占 640px 只有两列信息

10 行 × 「股名 + 次数胶囊」，占满整屏，信息量极低。

**建议**：改成横向 wrap 的紧凑 chip 流，或默认只显示前 5 条 + 「展开」。

### 15. Emoji 当图标

`📭 🟢 🟡 🔴 💡 📌 🗣️ 📅 📈 ✅ ❌ ⏸ ⚠️ ↗ 🔗` 混用。各平台（iOS / Android / Windows）
渲染差异大，且无法随主题变色、无法对齐基线。

**建议**：关键状态指示改用 SVG 或纯 CSS 图形；emoji 只保留在真正表达情绪的文案里。

### 16. 建议建立 design token（当前只有 8 个变量）

```css
:root {
  /* 现有 —— 颜色 8 个 + 圆角/阴影 */
  --bg --card --ink --ink-2 --ink-3 --line --brand --brand-soft
  --up --down --amber --amber-soft --radius --shadow

  /* 缺失 —— 导致 15 种字号和 13 种文字色的根因 */
  /* 字阶 */    --fs-11 --fs-12 --fs-13 --fs-14 --fs-17 --fs-22
  /* 间距 */    --sp-1:4px --sp-2:8px --sp-3:12px --sp-4:16px --sp-6:24px
  /* 风险档 */  --risk-high --risk-high-bg --risk-mid --risk-mid-bg --risk-low --risk-low-bg
  /* 排名阶 */  --rank-1 --rank-2 --rank-3 --rank-4 --rank-5
  /* 触控 */    --tap-min: 44px
}
```

## 四、不需要改的部分（避免过度设计）

- **信息架构**：5 个 Tab 的划分（早报 / 晚报 / 短线 / 量价 / 日历）合理，职责不重叠。
- **`.tabs` 的滑动下划线**（`#tabGlider`）实现干净，`transition` 参数也合适。
- **Tab 热区 72×44px** 达标。
- **轮询 + `applyUpdate()` 就地更新**（不整页刷新、保留 Tab 与浏览日期）是正确的移动端做法。
- **破缓存自检脚本**（比对 `?v=` 版本号）是这个项目特有的好设计。
- **`--font-variant-numeric: tabular-nums`** 在指标卡和表格里已经用对了。

## 五、建议的落地顺序

| 阶段 | 内容 | 影响面 | 风险 |
|---|---|---|---|
| **第 1 步** | 加 design token（字阶/间距/风险档/排名阶）+ `--ink-3` 提深 | `style.css` 变量区 | 低，纯变量 |
| **第 2 步** | 按 token 替换 15 种字号与 13 种文字色 | `style.css` 全文 | 低 |
| **第 3 步** | 拆掉 `nth-child` 硬编码配色，改语义 class | `style.css` + `app.js` 少量 | 中，需截图逐 Tab 比对 |
| **第 4 步** | 量价表滚动引导 / 日历原图折叠 | `style.css` + `app.js` | 中，改渲染逻辑 |
| **第 5 步** | `.tabs` sticky + header 桌面端限宽 | `style.css` | 低 |

每步改完按项目规则（AGENTS.md 第 7 条）**先本地 Edge headless 截图验证 5 个 Tab 再交付**，
并且跑 `node tools/test_health_logic.js` 确认时间相关判定未被影响。
