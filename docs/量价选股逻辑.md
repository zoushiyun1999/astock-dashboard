## 二、数据源（已验证可用，含踩坑记录）

| 数据 | 接口 | 说明 |
|---|---|---|
| 涨幅 / 换手 / 市值 / 量比 / 代码 | `push2delay.eastmoney.com/api/qt/clist/get` | 延迟 15 分钟，收盘后跑无影响 |
| 连续收阳（日K） | 新浪 `money.finance.sina.com.cn/.../getKLineData` | **主源，稳定** |
| 连续收阳（备用） | 腾讯 `web.ifzq.gtimg.cn/appstock/app/fqkline/get` | 高频请求会触发 WAF 拦截，仅作备用 |
| 分时均线 | `push2delay.eastmoney.com/api/qt/stock/trends2/get` | 返回每分钟价格(f53) + 均价(f58) |

### ⚠️ 已踩过的坑（改脚本时注意）

1. **`push2.eastmoney.com` 和 `push2his.eastmoney.com` 在本机网络下不通**（连接失败/返回空），必须用 `push2delay.eastmoney.com`
2. **腾讯 K 线接口会被 WAF 拦截**——跑几十次后返回 HTML 风控页而非 JSON。脚本已内置检测（响应含 `<!DOCTYPE` 或 `waf.tencent` 即判定失败并切换备用源）
3. 高频请求会限流，脚本并发控制在 4，失败自动重试 2 次（约 10 只左右可能因网络抖动失败，属正常）

## 三、执行流程

```
① 拉沪深主板全市场（3485 只）
        ↓  一次分页请求，约 1 秒
② 基础条件过滤（涨幅/换手/市值/量比/排除）
        ↓  约 179 只
③ 逐只查日K → 连续收阳 ≥2 天
        ↓  约 84 只
④ 逐只查分时 → 全天在均线上方
        ↓  约 31 只
⑤ 按涨幅排序，取前 40 只
        ↓
⑥ 标注「是否属于当日主线板块」（从 data.js 的 板块热点 提取股票名做匹配）
        ↓
⑦ 写入 data.js 顶层 screener 字段
```

**总耗时约 30-60 秒。**

## 四、数据结构

```json
"screener": {
  "date": "2026-08-31",
  "runAt": "2026-08-31 22:47",
  "count": 31,
  "criteria": {
    "gain": "2.5%-7%", "turnover": "2.5%-20%", "cap": "20亿-500亿",
    "volRatio": ">1", "yang": "≥2连阳",
    "aboveAvg": "≥95% 时间在分时均线上",
    "exclude": "创业板/科创板/北交所/ST/退市"
  },
  "list": [
    {
      "code": "603819", "name": "神力股份", "price": 26.13,
      "gain": 6.81, "turnover": 4.09, "volRatio": 2.04, "cap": 33,
      "yang": 5, "aboveRate": 99, "sector": ""

```

`aboveRate` = 价格在分时均线上方的时间占比（百分比）
`sector` = 若该股属于当日主线板块则填板块名，否则为空字符串

## 七、常见调整方向

- **池子更严**：涨幅改 3%-6%、连续收阳改 ≥3 天、均线上方占比改 100%
- **只看强势**：按量比排序（`final.sort` 改为 `b.f10 - a.f10`）
- **放开市值上限**：`capMax` 改 1000（纳入大市值蓝筹）
- **加入题材维度**：把 `sector` 非空的排在前面，或直接只保留 `sector` 非空的（技术面 + 热点共振）
- **加均线/趋势条件**：需要在脚本里额外拉日K 计算 MA5/MA10/MA20，当前已拉到 10 天日K 数据可直接扩展
